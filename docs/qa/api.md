# aisa-api (rute, perintah, intake, ringkasan) — matriks penerimaan

Penguji: agent penguji pytest (bukan penulis kodenya). Ditulis dari `services/api/README.md`
(tabel rute, "Behaviour worth knowing", perintah WhatsApp), `GLOSSARY.md`, dan celah di
[`inventaris-fitur.md`](inventaris-fitur.md) sebelum membaca implementasinya; teks balasan
dikutip dari kode karena itulah yang dikirim ke WhatsApp.

Lingkungan: lokal, lapis **py** saja (`services/api/tests/`), commit dasar `85539f6`,
2026-10-21. Firestore, GOWA, GCS, Drive, dan model diganti tiruan di
`services/api/tests/conftest.py` (Firestore dalam memori, GOWA yang mencatat pengiriman, model
yang diskrip). Tidak ada panggilan jaringan, tidak ada revisi Cloud Run, tidak ada engine Agent
Runtime. Anggaran pesan WA: 0.

Batas lapis ini: Firestore tiruan tidak membuktikan indeks komposit, aturan keamanan, maupun
semantik transaksi sungguhan; "terkirim" berarti `gowa.send` dipanggil, bukan pesan sampai di
WhatsApp. Baris yang butuh bukti itu tetap perlu penerimaan di produksi.

## Temuan

1. **Webhook 500 untuk JSON bertanda tangan yang bukan objek** —
   `services/api/aisa/main.py:142` memanggil `ev.get(…)` setelah `json.loads` (`:139`) tanpa
   memastikan `ev` adalah objek. Body `null` atau list yang bertanda tangan sah menghasilkan
   500, bukan `{"ignored": …}`. README menjanjikan hanya `event: message` yang diproses dan
   yang lain diabaikan. Dampak rendah (hanya pemegang `GOWA_WEBHOOK_SECRET` yang bisa
   mengirimnya), tetapi GOWA bisa mengulang kiriman yang dibalas 500. Tes:
   `test_routes.py::test_pwa_w06_signed_json_that_is_not_an_object_is_ignored` (xfail strict).
2. **Token proposal hilang di jalur Perlu dicek manual** — `finish_manual` di
   `services/api/aisa/intake.py:125` menulis `tokens` dengan token run ini saja, sedangkan
   jalur `dinilai` dan `dihentikan` menambahkan lewat `_spent` (`intake.py:212`, docstring:
   "every run spends tokens, so they accumulate"). Proposal yang dihentikan STOP setelah
   memakai token, lalu dijalankan ulang setelah LANJUT dan berakhir Perlu dicek manual,
   kehilangan token run pertamanya; angka token di detail proposal tidak lagi sama dengan
   jumlah token job-nya di Aktivitas AI. `aisa-firestore.md` menyebut `tokens` "sum over this
   proposal's penilaian job" — kontrak perlu memutuskan apakah itu satu job atau semua run.
   Tes: `test_intake.py::test_pnl_08_tokens_accumulate_across_runs_on_the_manual_path` (xfail
   strict).

Tidak ada flake: suite dijalankan tiga kali berturut-turut dengan hasil sama.
